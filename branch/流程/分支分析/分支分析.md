# 分支分析

对大纲的每个岔路做正反双链自辩，再定语言/库/算法分支。

## 分析维度

1. **语言与运行时**：生态成熟度、目标平台、团队既有栈。
2. **库与框架**：维护状态、许可证、依赖体积、是否需网络授权获取文档。
3. **算法与数据结构**：复杂度上界（参考 [cppreference 容器与算法复杂度](../../../references/标准与工具/cppreference.md)）。
4. **架构模式**：分层/事件/管道，取舍写清（参考 [Effective Modern C++ 惯用法](../../../references/工程实践/effective-modern-cpp.md)）。
5. **风险分支**：并发、IO、编码、时区、精度、外部 API 限流。

## 动作

- 每个岔路一次辩论：`python -B scripts/logic_chain.py debate --pro <正方> --con <反方>`，裁决记逻辑链。
- 结论落 `tmp/branch-decision.md`：选项、裁决、理由、被否方案。
- 任一维度信息不足 → 立即转 [浏览器学习](../浏览器学习/浏览器学习.md)。

## 兜底

- 双链势均：选依赖更少、可测试性更强的一支，并记 TODO 复验。
