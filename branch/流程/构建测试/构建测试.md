# 构建测试

编译/运行/测试全绿才算完成，失败即回脚本构建。

## 动作

1. 构建：`python -B scripts/run_tests.py --path tmp/<proj> --dry-run` 预览命令，确认后执行。
1b. 探针自检（本技能必跑八项，全部 rc=0 才算过）：
    `classify_topic.py --file tmp/bad.cpp --json` · `knowledge_index.py --list` ·
    `ownership_audit.py tmp/bad.cpp` · `const_audit.py tmp/bad.cpp` ·
    `concurrency_probe.py tmp/bad.cpp` · `perf_advice.py tmp/bad.cpp` ·
    `cmake_probe.py --dir .` · `advice_compose.py --topic raii-ownership --evidence probe`
2. 测试分层：单元（函数级）→ 集成（模块协作）→ 端到端（真实入口）。
3. 覆盖边界：空输入、极值、非法类型、并发竞态、外部依赖不可用。
4. 失败处理：贴出最小可复现片段 → 记 `process_chain.py interrupt` → 回 [脚本构建](../脚本构建/脚本构建.md) 修复 → `resume`。
5. 报错原因不明 → 转 [浏览器学习](../浏览器学习/浏览器学习.md) 检索错误码/文档，禁止猜测式反复改。

## 产出

- `tmp/test-report.md`：用例数、通过率、失败清单、覆盖率。
- 逻辑链一条：测试结果 → 是否可交付的裁决。

## 兜底

- 环境缺依赖导致无法运行：报告缺项并给安装指引，不得以「代码看起来对」充当通过。
- 重试达 10 次：`penalty.py hit` 熔断，回退本步或求助用户。
