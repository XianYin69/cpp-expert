# 需求确认

接收编程任务后先澄清，再动手；区分创建 or 修改。

## 必答清单

1. **输入/输出**：数据形态、边界值、失败期望行为。
2. **语言与运行时**：版本、目标平台、是否已有工程。
3. **规模与性能**：数据量级、时延/内存约束、并发要求。
4. **验收标准**：可执行的测试或判据（无判据＝需求未确认）。
5. **路径判定**：新建工程/模块 → 创建流程；改既有代码/技能 → 修改流程。

## 动作

- 缺项一次一问向用户确认（`ask_user`），禁止用假设填补关键需求。
- 每条判定写逻辑链：`python -B scripts/logic_chain.py add logic_chain.jsonl --from 需求确认 --to <判定> --why <理由>`。
- 存档：`python -B scripts/process_chain.py save --step 需求确认 --data '{"...": "..."}'`。

## 兜底

- 用户不响应或需求持续模糊：出流程图辅助澄清（`scripts/flowchart_helper.py`），仍不明则熔断求助。
