# 大纲构建

把需求拆成模块与接口，形成可审阅的实现大纲。

## 动作

1. 列模块：入口、核心逻辑、数据层、接口/CLI、测试。
2. 定接口：函数签名、输入输出类型、错误约定（异常 vs 返回码）。
3. 定文件布局与命名（遵循 [code-guidelines](../../../dependence/dependence.md) 声明的准则）。
4. 标出风险点与待验证假设（供分支分析与浏览器学习消费）。
5. 大纲交用户审阅确认后再进入分支分析；确认结论写逻辑链。

## 产出

- `tmp/outline.md`：模块表 + 接口表 + 风险清单（≤50 行，超则拆子文档）。
- 每模块一条 `process_chain.py save --step 大纲构建 --data '{"module":"..."}'`。

## 兜底

- 大纲与需求冲突：回 [需求确认](../需求确认/需求确认.md) 重澄清，禁止私自缩减范围。
- 规模过大：先切 MVP 子集交付，其余列 TODO 并告知用户。
